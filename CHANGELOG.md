Общие компоненты: `Tabs`, `SegmentChoice`, `Breadcrumbs`, `EvaluationStamp`, `Stepper`, таблицы, поля выбора, радиокнопок, даты, времени и количества. Это организации и рестораны, страница организации с вкладками «Рестораны», «Участники», «Приглашения», «Профиль организации», страница участника с матрицей «ресторан × роль», форма приглашения, «Создать предприятие» с выбором часового пояса и оболочка «Нет доступных ресторанов». Данные — временные, из `placeholder-organizations.ts`; неизвестный идентификатор в адресе ведёт на 404. Общие компоненты: `Dialog`, `ModalPanel`, `TabNav`, `SearchInput`, карточки; в тему добавлены `bg.scrim` и запросы `atLeast.sm` и `media.sm`.
- Исправлены детали оболочки по Figma: текст в диалогах и меню больше не чёрный (браузер красит `<dialog>` в CanvasText), плейсхолдеры полей — цвета `text.secondary`, логин в меню — моноширинный, стрелка кнопки учётной записи смотрит вверх.
- Исправлен чекбокс: у отмеченного поля не было галочки. Vite встраивает маленькие SVG как `data:` URI, а `url()` без кавычек вокруг такого URI — недопустимый CSS, и браузер отбрасывал `background-image`. Это касалось «Запомнить меня» и согласия в форме обратной связи. Тест `tests/quality/css-url.test.mjs` не пропускает `url(${…})` без кавычек.
- Добавлены экраны входа и восстановления пароля с кодом из письма по Figma: `/login`, `/password-reset`, `/password-reset/code`, `/password-reset/new`. Это была первая версия, только внешний вид. Сейчас вход и сброс пароля подключены к gateway (см. пункты выше).
- Добавлена пустая оболочка `/app`. В неё входят боковая панель (на 390 — верхняя панель и выдвижная навигация), меню учётной записи на нативном `<dialog>`, пустой «Обзор», пустые разделы и страница «Учётная запись» `/app/settings`. Имя и ресторан — временные данные макета из `placeholder-account.ts`.
- Новые общие компоненты: поле пароля с кнопкой показа, поле кода, иконка-маска. Новые виды декора: свечение, круг, кольцо. В тему добавлены стиль `mono.code` и отступ `11`.
- Ссылки «Открыть приложение» ведут на `/login`.
- Тексты лендинга, баннера cookie и подвала документов приведены к актуальному Figma. Время подписано зоной «(Москва, UTC+3)», упоминания «одного ресторана» заменены на организацию. В иллюстрации добавлен раздел «Аналитика».
- Добавлены smoke-тест серверного рендера маршрутов и тест, что временные данные учётной записи лежат в одном модуле.
- Nginx передаёт поток `GET /api/live` через отдельный `location`: HTTP/1.1 с пустым `Connection`, без буферизации, кеша и gzip, таймаут чтения 60 с, с заголовками браузера и JSON-ошибками `502` и `504`. `npm run test:nginx` проверяет поток с заглушкой gateway.
- Live-sync доступен экранам через `ServicesProvider` и хуки `useLiveState` и `useReadModel`. Поток не запускается, пока нет экранов `/app`.
- Фоновые чтения после сигнала потока или такта отправляют `X-Umir-Activity: background` и не продлевают сессию. Чтения по действию оператора идут без заголовка. После закрытого потока live-sync проверяет сессию фоновым `GET /api/operator/me`, чтобы при `401` показать «сессия истекла», а не переподключаться каждые 3 с.
- Добавлены адаптеры видимости вкладки и таймеров браузера для live-sync.
- Добавлены модели чтения экранов. Применяется только ответ на последний запрос по счётчику клиента, а сигналы во время запроса дают ровно один следующий запрос.
- Добавлен сценарий live-sync. Номера изменений сравниваются в пределах `epoch`, новый `epoch` перечитывает всё, `tick` перечитывает модели, зависящие от времени, а `session-ended` останавливает поток без переподключения. Через 10 с без открытого потока или при `upstream: false` включается состояние устаревших данных. Скрытая вкладка откладывает перечитывание. Закрытый поток подключается снова через 3 с, если проверка сессии не показала, что сессия закончилась; иначе live-sync останавливается с причиной `expired`.
- Добавлены порт `LiveFeed` и адаптер потока `GET /api/live` на `EventSource`. Данные каждого события проверяются во время выполнения, `seq` хранится как `BigInt`, а некорректное событие закрывает поток.
- Добавлена публичная часть «Ровного хода» по макету Figma. В неё входят лендинг на `/`, политика конфиденциальности, политика cookie, текст согласия, баннер cookie и страница «Страница не найдена». Подключены Chakra UI с собственной темой из токенов макета, react-router и шрифты IBM Plex через `@fontsource`. В `tsconfig.json` включён `skipLibCheck`, потому что типы Ark UI несовместимы с `exactOptionalPropertyTypes`.
- Форма обратной связи проверяет поля по контракту umir-feedback#1 и повторно использует `submissionID` для того же черновика.
- Добавлены фавиконки, `favicon.ico` и `manifest.webmanifest`. Docker-сборка теперь копирует `public/`, а Nginx отдаёт манифест с типом `application/manifest+json`, которого нет в стандартном `mime.types`.
- Оглавление документов подсвечивает текущий раздел до конца страницы. Короткие последние разделы получают свой участок прокрутки. Раздел, выбранный в оглавлении или по ссылке с якорем, остаётся выделенным, пока читатель не прокрутит страницу.
- В блоке «Возможности» на планшете и компьютере белые панели карточек одного ряда начинаются и заканчиваются на одной линии при любой длине заголовка и описания. На телефоне панель по-прежнему показывает фрагмент фиксированной высоты.
- Страница «Страница не найдена» занимает всю высоту окна и показывает крупную декоративную цифру 404. В её шапке только логотип.
- Добавлены unit-тесты Bun для проверки полей обратной связи, сценария отправки, хранилища cookie-уведомления и выбора текущего раздела в оглавлении.
- Переведён пустой каркас на TypeScript и зафиксирована пятислойная архитектура: domain, application, adapters, presentation и app. Добавлены ESLint, dependency-cruiser, Prettier и Bun 1.4.3 с положительными и отрицательными сценариями архитектурных правил.
- Документированы команды проверки, CI и границы backend/frontend. Для будущих экранов сохранены runtime-проверка API, генерация типов из закреплённой OpenAPI, HTTP-моки и браузерная приёмка; экраны, API-клиент и E2E-проверки в этот этап не входят.
- Chakra UI оставлена выбранной для будущих экранов, но пока не устанавливается. Prettier обрабатывает SCSS; семантическая проверка стилей отложена до появления production-стилей.
- Expanded the approved frontend stack to JavaScript or TypeScript, SCSS and Chakra UI on React/Vite after inspecting the organizer's presentation. Authorized openapi-typescript and Playwright as future additions; Bun is the selected test runner.
- Браузерная приёмка использует реальные serving/warehouse через frontend/gateway; документы согласованы с межмодульными и HTTP-проверками фабрики.
- Прокси API (gateway#8, gateway#10): `Host` браузера передаётся вместе с портом; конечные таймауты (5 с соединение, 30 с отправка и чтение), без повторов и кеширования; собственные ошибки Nginx `502`, `504` и `413` — JSON в формах gateway вместо HTML; `POST /api/feedback` ограничен 16 КиБ. `npm run test:nginx` и CI проверяют `nginx.conf` с заглушкой gateway.
- Documented how to maintain README, AGENTS and changelog alongside implementation, with separate current, approved and planned status and exact API revision references.
- Обновлены закреплённые GitHub Actions до выпусков с поддержкой Node.js 24.
- Уточнены границы готового ядра, целевого OpenAPI и следующего этапа интерфейса.
- Обновлены закреплённые версии Node.js и Nginx; CI использует Node.js 24.21.0.
