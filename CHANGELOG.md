# Изменения

## Не выпущено

- Поля форм поставки и блюда типизированы: дата — сегменты «дд.мм.гггг» и свой календарь, время — маска «чч:мм» и список через 30 минут, продукт — список с поиском по названию или коду, количество принимает только цифры и запятую (до 0,001), срок годности — счётчик дней. Системные `<select>` и текстовые даты удалены; имена полей и разбор формы поставки не изменились. Новые slot-рецепты темы: `combobox`, `dateInput`, `datePicker`. Строки поставки собираются в таблицу от 1420px, на более узких экранах остаются карточками.

- При объединении карты и новых текстов сохранены сведения о cookie Яндекса. У абсолютных дат истории и партий остаётся год; уведомления о принятом приглашении сообщают о подготовке к отправке.

- Тексты интерфейса переписаны простым языком сайта: сервис говорит «мы», к пользователю — «вы», без названий внутренних сервисов, «попыток», «оценок», «предложений» и FEFO. Словарь: «аккаунт», «организация», «почта», «устройства», «рецепт», «можно использовать», «настраивается». Неизвестный исход по-прежнему не выдаётся за успех или отказ: «Не знаем, …» и «Проверить результат».
- С экрана убраны технические данные: `commandID`, `proposalID`, код `CommandConflict`, ID заказа, внутренние номера партий и событий истории. Партия называется продуктом и сроком годности; код ошибки остаётся только в «Подробностях для поддержки» с подписью «Код ошибки».
- Время — «14 октября, 10:00» без секунд и UTC; шапка раздела называет город один раз («Среда, 14 октября · Москва»); часовой пояс — «Москва (UTC+3)» без идентификатора IANA.
- Количества, коды, логин и время в таблицах набраны основным шрифтом с цифрами одной ширины (`numeric.*`); моноширинный шрифт остался только у кода из письма.
- В похожем на почту логине нормализуются крайние пробелы, NFC и регистр домена (issue #11); обычные логины и пароль сохраняются без изменений.

- Страница регистрации `/register` с подтверждением почты кодом. Запросы используют принятый контракт REG1 из Factory `4374042`; Auth требует включённую настройку `registration.enabled`.
- Запросы участников, приглашений и профиля организации отменяются при очистке моделей и окончании сессии. Поздний ответ не обновляет экран и не запускает следующую страницу списка.
- Подключены к backend v2 (контракт FIN1, область Auth) организации, участники и приглашения; проверены тестами по контракту:
  - список организаций и ресторанов из `GET /api/v2/access`, страница организации, «Создать предприятие» и «Добавить ресторан» с шкалой подготовки; подготовка наблюдается через `GET …/lifecycle/{operationID}`;
  - профиль организации и смена часового пояса со всеми исходами (неизвестная зона, устаревшая версия, каталог зон не готов, роль снята); список зон — статический IANA, смещение считает `Intl`;
  - списки участников, приглашений и профиль читаются при каждом открытии страницы, на страницах участников и приглашений есть «Обновить»; команда, запрос которой ещё идёт, не показывается как «Результат … неизвестен»;
  - участники и страница участника с матрицей «ресторан × роль»: назначения, отзыв доступа и отзыв собственного доступа без «Открыть»; устаревшая версия и отозванное членство перечитывают список, последний администратор показывается отказом;
  - роль «Администратор» выдаётся и снимается в карточке участника;
  - приглашения: форма с матрицей готовых ресторанов, ссылка приглашения, повтор ссылки, отмена, срок и состояние в зоне организации; почта, которая уже в списке участников, отклоняется на клиенте;
  - удаление ресторана и организации с наблюдением за операцией;
  - страница приглашения `/invite/:invitationID`: имя и пароль для нового пользователя либо запрос кода для вошедшего, затем код из письма; вызов кода переживает перезагрузку вкладки (`sessionStorage`, ключ `umir.invite`), пароль не сохраняется; адрес возврата после входа допускает ровно `/invite/<UUID>`;
  - «Сеансы» в «Учётной записи»: выход на всех устройствах, неизвестный исход проверяется повтором той же команды с тем же `commandID` (`401` на повторе означает, что выход выполнен, `401` на первой попытке — истёкшая сессия);
  - обратная связь из приложения: `/app/r/:restaurantID/feedback`, `POST /api/v2/r/{restaurantID}/feedback`; отправитель обратной связи общий с лендингом и принимает путь;
  - команды администратора хранят введённые значения попытки с неизвестным исходом: «Проверить результат» повторяет её с тем же `commandID`, новая попытка с новым ID не создаётся;
  - Nginx отдаёт `/invite/` с `Referrer-Policy: no-referrer`; `npm run test:nginx` проверяет заголовок;
  - если обновление `GET /api/v2/access` не удалось, хранилище доступа сохраняет последний готовый ответ (`knownOrganizations`), и страницы организаций показывают его; диалог `ModalPanel` можно закрыть только после ответа на команду (`locked`).
- Удалены макеты экранов организации из `examples/ui-prototype`: `organizations/*`, `placeholder-organizations.ts` и тест `placeholder-organizations.test.mjs`; экраны организации работают на Auth.
- В «Контактах» лендинга вместо схемы — карта Яндекс Карт с адресом офиса: Ростов-на-Дону, ул. Тургеневская, 10/6; часы поддержки — пн–пт, 9:00–18:00. Политика конфиденциальности, политика cookie и уведомление о cookie сообщают, что при показе карты ООО «Яндекс» получает данные запроса и может установить свои cookie.

- Добавлен сценарий live-sync. Номера изменений сравниваются в пределах `epoch`, новый `epoch` перечитывает всё, `tick` перечитывает модели, зависящие от времени, а `session-ended` останавливает поток без переподключения. Через 10 с без открытого потока или при `upstream: false` включается состояние устаревших данных. Скрытая вкладка откладывает перечитывание. Закрытый поток подключается снова через 3 с, если проверка сессии не показала, что сессия закончилась; иначе live-sync останавливается с причиной `expired`.

- Added repository development and release rules; that documentation change did not alter the frontend toolchain.

### Добавлено

- Подключение к backend v2:
  - HTTP-клиент gateway с CSRF и исходами потерянных ответов;
  - команды с `commandID`, эпохи сервисов, модели данных по темам потока;
  - сессия, вход паролем и выход (`/logout`);
  - доступ и права по ролям ресторана.
- Адреса разделов ресторана `/app/r/:restaurantID/…`; `/app` открывает последний или первый доступный ресторан.
- Состояния доступа из Figma: W10–W17, «Данные обновились».
- Закреплённый контракт `api/` и проверка `npm run api:check`.

### Изменено

- Поток обновлений — `GET /api/v2/r/{restaurantID}/live` с событиями `change`, `refresh-required` и `access-ended`.
- Nginx: поток v2, лимит 16 КиБ для обеих форм обратной связи, ошибки Nginx в форме `#Error`.
- Политика cookie: `umir.lastRestaurant`, `__Host-umir_operator_preauth`, сроки сессии.

### Удалено

- Шаг входа с кодом `/login/code` (решение 13.10).
- Адаптеры v1 `/api/live` и `/api/operator/me`.
